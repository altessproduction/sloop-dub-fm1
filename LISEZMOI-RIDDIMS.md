# SLOOP Dub FM-1 — la banque Riddim Collection (75 riddims)

Ce dépôt est le firmware **SLOOP Dub 1.8** (M-VAVE FM-1) dont **la banque de riddims est toute la
page [Riddim Collection](https://altessproduction.github.io/Riddim-collection/riddims.html)
(Altess Production)** : les 38 riddims du *Riddim Real Book (Tab)*, les 36 du pack « RIDDIM MIDI »
et le classique Sleng Teng (Jammy's, 1985) — soixante-quinze riddims, dans l'ordre de la page, avec
**la basse en piste 1, le skank en piste 2, l'instrument restant en piste 3 et la batterie en
piste 4**. Chaque riddim est une séquence de **64 pas (4 mesures de doubles-croches) qui tourne en
boucle**.

## Le paquet à installer

`sloop-dub-1.8.fwsc` — construit avec `./build.sh --release 1.8`
(identité **FM-1_234**, la même que le 1.7 officiel ; projets, presets, samples et réglages
conservés à la mise à jour). Image 580 736 o pour un slot de 581 564 o — **828 o de marge**.

## La banque compressée (1.8)

La banque brute des 27 du 1.7 pesait 13 932 o (516 o par riddim) ; les 75 bruts demandaient
~38 700 o — le slot n'a jamais pu les prendre. Chaque piste est donc stockée **compressée** :

- 1 octet d'en-tête : le nombre de **mesures sources** distinctes (0 = piste vide, 1..4) ;
- pour 2 ou 3 mesures sources : 1 octet de carte, deux bits par mesure jouée (1 source = jouée
  partout, 4 sources = l'identité) ;
- puis, mesure source par mesure source : 1 octet de compte, puis l'événement par hit —
  `{pas dans la mesure, code de note (0..127 ou DUB_SEQ_CUT 253), vélocité}`.

`dub_riddim_dec()` (`firmware/src/dub.c`) décompresse le flux dans les 64 pas du `dub_seq_t` au
chargement : en RAM, la séquence reste la grille complète, lisible et éditable comme avant —
les TIE tiennent les silences, les coupures `DUB_SEQ_CUT` finissent les notes tenues. Les mesures
d'un même riddim étant souvent identiques (les boucles du genre), la banque compressée des 75
(10 911 o de flux) est **plus petite que la banque brute des 27** qu'elle remplace.

Les arrangements longs de la page (Fade Away : 16 mesures, Freedom Blues : 20 mesures, sa basse
n'entrant qu'à la cinquième) bouclent sur les **quatre mesures qui suivent la première mesure
sonante de la basse** : les 64 pas tournent sur le groove complet, l'intro silencieuse reste
dehors.

## Comment la transcription a été faite

Le générateur **`tools/gen_riddims_web.py`** lit la grille de la page
(`tools/riddims_db.js`, la base `window.RIDDB` du site) et écrit
`firmware/src/dub_riddim.h` :

- **Basse (piste 1)** : les mesures de la page, bouclées sur les quatre bars, notes telles
  quelles (grille en doubles-croches), vélocités de la page (112 au temps, 96 hors temps) ;
  les longueurs de notes reviennent en tenues (TIE) et en coupures `DUB_SEQ_CUT` (253) —
  chaque note écrite ré-attaque, même au même pitch.
- **Skank (piste 2)** : quand la page a un accompagnement *skank* ou *guitare* (ou des
  accords), ce sont ses stabs — leur racine nourrit l'accord que la page **SKK** de la
  machine construit (MAJ/MIN/7TH…, octave réglable) ; sinon, contretemps classiques
  2 · 6 · 10 · 14 sur les racines de la grille d'accords de la page.
- **Piste 3 (l'instrument restant)** : l'autre accompagnement de la page — orgue, cuivres,
  deuxième accords ou mélodie —, la note du haut par temps, tenues et coupures respectées.
  Les riddims que la page joue basse-et-drums seulement laissent la piste 3 **vide** (à vous
  de la jouer).
- **Batterie (piste 4)** : le pattern propre du riddim quand la page en a un (le pack, le
  Sleng Teng), sinon celui de son style. La banque tient **une note de drum par pas** : là
  où la page empile kick et caisse claire (Sleng Teng) ou kick et rim (le one-drop), le
  **kick entre une double-croche avant** (le pickup du sound system) et les charleys
  déplacés sortent ; les ghosts restent doux (niveau GHOST).

Les noms courts (l'écran tient quatorze caractères) : CREATED FATHER, DEATH IN ARENA, ETHIOPIAN
KINGS, PICK UP PIECES, PRESSURE SLIDE, SATTA MASSAGA, WARRIORS CRY, CHERRY OH BABY, GRAB YR LASS,
RUN DOWN WORLD, JOHNNY DOLLAR, PEANIE PEANIE, ROCKFORT ROCK, FREEDOM BLUES, GHETTO PEOPLE…
— le nom complet de la page est dans le tableau ci-dessus et dans le README.

## Vérifications faites

- **Aller-retour en C** (`tools/verify_riddims.sh` + `tests/riddim_check.c`) : le générateur
  réécrit la banque compressée et les grilles brutes du même passage ; le test charge les 75
  riddims **par le chargeur du firmware** (`dub.c` compilé) et compare au `memcmp` les 4 pistes ×
  64 pas, notes **et** vélocités, plus les chargements piste à piste (aucune fuite dans les autres
  pistes) et le repli des index hors banque. Sortie : `riddim_check: 75 riddims x 4 tracks x 64
  steps, notes and velocities: OK`.
- **Recroisage avec le 1.7** : les grilles des 27 riddims déjà dans le 1.7 sont **identiques pas
  à pas** (notes et vélocités) à celles du 1.7 — seul l'encodage change.
- **Compile C** : `gcc -std=c99 -Wall -Wextra` propre sur `dub.c` + le test ;
  `sizeof DUB_RIDDIMS/…[0]` = 75.
- **Build complet** avec la toolchain JieLi (clang 4.0.1 pi32v2) : toutes les vérifications
  du build passent (`image 580 736 B`, accès registres, RAM) ; la banque tient le slot avec
  828 o de marge.
- **Émulateur web** : le smoke test (`reference_emu/wasm_smoke_test.js`) passe sur le
  `sloop.wasm` reconstruit — compte 75, les noms de la page, le readback du chargeur
  (basse AFRICAN BEAT, stutter SLENG TENG), le transport qui joue.

## Reconstruire la banque / le firmware

```
sh tools/verify_riddims.sh              # la preuve du aller-retour (génère + teste)
python3 tools/gen_riddims_web.py        # réécrit firmware/src/dub_riddim.h depuis la grille
./build.sh                              # build dev (identité FM-1_900)
./build.sh --release 1.8                # build installable (identité FM-1_234)
sh reference_emu/build.sh               # l'émulateur web (clang wasm32, ou zig : CC="python3 -m ziglang cc")
node reference_emu/wasm_smoke_test.js   # le smoke test de l'émulateur
```

La toolchain et l'SDK : voir BUILDING.md (`tools/get_toolchain.sh`, clone AC79
AC79NN_SDK_V1.2.1_2023-12-13). L'aperçu de l'éditeur : `sh scripts/build_preview_wasm.sh`.
